What's actually slow isn't always what you'd guess

File size on disk correlates loosely with how hard a file is to open, but it's not the whole story. A workbook full of formatting bloat — conditional formatting rules applied to entire unused columns, or thousands of unique cell style combinations built up over repeated edits — can be small in megabytes and still take Excel a long time to render and calculate, because Excel has to process every one of those rules and styles on open regardless of whether the cells they apply to contain data.

Why it can crash rather than just be slow

32-bit Excel installations are limited to roughly 2GB of addressable memory no matter how much RAM the computer has; a file with heavy formatting, many formulas, or large embedded images can exceed that ceiling and crash outright rather than just running slowly. 64-bit Excel raises that ceiling substantially, but even it can struggle with files that were never designed to be opened interactively — ones built as data exports rather than working spreadsheets.

Seeing what's inside without opening it in Excel

An xlsx file is a zip archive of XML files under the hood — sheet dimensions, row counts, and structure can be read directly from that XML without loading the file into Excel's calculation engine at all, which is what lets a file too heavy for Excel to open safely still be inspected. Upload it below to get sheet names, dimensions, and row/column counts without your machine ever having to render or calculate the file.

What to do once you know what's inside

If the inspection shows the bloat is concentrated in formatting rather than data — conditional formatting on entire unused columns is a common find — that's fixable by trimming the applied ranges down to where your actual data lives, which is often the fastest way to make a slow file usable again.
