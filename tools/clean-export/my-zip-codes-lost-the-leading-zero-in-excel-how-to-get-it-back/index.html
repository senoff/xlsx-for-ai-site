My zip codes lost the leading zero in Excel — how to get it back

Zip codes like 02138 showing as 2138 in Excel? The General number format silently drops leading zeros because Excel decided the column is numeric. Here's why, and how to get the zero back

clean-export · xlsx-for-ai

What Excel is actually doing to the value

Under General format, Excel checks whether what you typed looks like a number, and if it does, it stores it as a true numeric value rather than as text. A true number in Excel — like in ordinary arithmetic — simply has no concept of a leading zero: 02138 and 2138 are the same quantity, so Excel keeps the one without the zero. This isn't a display glitch; the zero is genuinely not part of the stored value anymore.

The two moments this happens

It can happen the instant you type a zip code into a General-formatted cell — Excel converts it to a number on entry, before you've even pressed Enter on the next cell. It can also happen during a CSV import: Excel's importer inspects each column and, if every value looks numeric, converts the whole column to numbers on the way in, even if the source file had the zero written out as a plain character.

How to get the zero back — and keep it

If the zero is already gone from cells that are now storing real numbers, reformatting the column afterward won't restore missing digits — you need to re-enter or re-import the original zip codes into cells that are already prepared to receive them as text. Format the destination column as Text (Format Cells > Text) before typing or pasting, or apply the custom number format 00000, which pads a stored number back out to five digits for display and for anything reading the cell as text. For CSV re-imports, use Data > Get Data / From Text and explicitly set that column's type to Text in the wizard rather than letting Excel auto-detect it. Note that a custom 00000 format only helps standard five-digit zips — it won't correctly represent a ZIP+4 code with a dash, which needs the Text approach instead.
