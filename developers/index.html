Using the raw HTTP API.

Every xlsx-for-ai tool is a plain HTTP endpoint you can call from any language — no SDK, no upload UI.

The MCP client is the easy path for Claude, Cursor, and other agents. But if you're integrating directly, the same 55 tools are a versioned HTTP API. You can browse the reference without a key; calling a tool needs a key, and the section below shows how to get one.

Signing in

Sign-in is with Google only. In an assistant or editor, install the package (npm install -g xlsx-for-ai@latest, version 4.2.1 or later) and make your first request. The package answers with a sign-in link shown right there in the assistant: open it, sign in with Google, then ask again. This works the same in a desktop app or editor with no terminal, and nothing needs a second machine. From a terminal you can also run xlsx-for-ai login, which prints a short code and a verification address to approve in your browser. Either way the client stores the key it receives.

Keys made without signing in (by earlier versions, or by registering with no credentials) still work. Signing in is recommended, and we will give notice before anything about those keys changes.

Plans and limits

There are two plans, and both are counted in files, never in file size. Xlsx Pro Free is 500 files a month for the first 1,000 people who sign in. Otherwise you get a 10-file trial, then Xlsx Pro at $25 a year for 10,000 files a month.

File-size limits are the same for everyone and are not something you can buy: .xlsx 100 MB, .csv 200 MB, .xls 100 MB, .xlsb 10 MB, any other type 10 MB. For a file over its limit, split it or convert it; the large-files page says how.

Claude Code plugin (one command)

In Claude Code 2.1.292 or later, one command adds the plugin and installs it. The plugin tells Claude what the hosted xlsx-for-ai tools do and when they fit: when the answer depends on formula results, on whether saved values are current, or on handing back a working spreadsheet file.

claude plugin install xlsx-for-ai --marketplace senoff/xlsx-for-ai

Then run /reload-plugins (or restart Claude Code), open /mcp, choose plugin:xlsx-for-ai:spreadsheets and sign in with Google once. If your Claude Code is older, run claude update first.

Claude app on claude.ai (nothing to install)

xlsx-for-ai is listed in the Claude connector directory. Open the directory, find xlsx-for-ai, click Connect, and sign in with Google when asked.

Any other MCP client that accepts a server address can add the hosted address https://api.xlsx-for-ai.dev/mcp as a remote server.

https://api.xlsx-for-ai.dev/mcp

Getting a key over plain HTTP

POST https://api.xlsx-for-ai.dev/api/v1/clients (no auth) returns { client_id, api_key }; then call any tool with an Authorization: Bearer <api_key> header. A key made this way has not signed in, so signing in (above) is recommended.

# Self-issue a key (no signup), then convert report.xlsx to Markdown.
# Needs jq, and bash or zsh. The base64 body is passed to curl through a
# process-substitution fd and the token through a --config heredoc on stdin, which
# keeps both out of the argument list. -fsS --max-time makes curl fail loudly on an
# HTTP error or a hang; the guard line stops on a failed key issuance.
KEY=$(curl -fsS --max-time 30 -XPOST https://api.xlsx-for-ai.dev/api/v1/clients \
  -H 'Content-Type: application/json' \
  -d '{"client_version":"2.0.0","platform":"cli"}' | jq -r .api_key)
[ -n "$KEY" ] && [ "$KEY" != null ] || { echo "key issuance failed"; exit 1; }

curl -fsS --max-time 120 -XPOST https://api.xlsx-for-ai.dev/api/v1/tools/xlsx_convert \
  --data-binary @<(base64 < report.xlsx | tr -d '\n' | jq -Rs '{file_b64: ., to: "md"}') \
  -H 'Content-Type: application/json' \
  --config - <<CFG
header = "Authorization: Bearer $KEY"
CFG

Discover the whole API — no key required

The same governed contract is served read-only from two routes, so you can explore before you register:

  • GET /api/v1/reference
    A self-contained human HTML reference for all 55 public-stable tools plus the 2 documented session tools (xlsx_read_handle, xlsx_session_set_validations), including the on-ramp above.
  • GET /api/v1/openapi.json
    The versioned OpenAPI 3.1 contract, verbatim. Point codegen, Postman, or Scalar/Redoc at it.

Errors and the convert refusal

Every error body has the same shape: { "error": { "code", "message" } }. The code is the stable key to branch on, and the message is the self-correcting detail that says what was wrong and what to change. A few codes add a documented extra field, such as available_sheets when a sheet name is not found, but there is no finer error-subtype field in the response.

When our own engine cannot produce the output you asked for from an xlsx, xls, csv or json file (most notably to=xlsx), xlsx_convert returns a typed HTTP 501 with the error code capability_gap and does not fall back to a compatibility library. This is not a client error and it is not transient, so retrying the same file does not help. Through the MCP connector the same refusal arrives as a tool result with isError set to true, carrying the same message. Formats such as ods, xlsb, fods and the xls (BIFF8) write target are served by the legacy path and are unaffected.

Recalculating a read. Set options.evaluate: true (or the top-level evaluate: true; they are the same switch, and sent with different values the call is a 400) to have xlsx_read recalculate every formula: every cell, array and data-table cells included, on every page, is the recalculated value or #UNSUPPORTED!, never the value saved in the file, and _meta.recalculated says so.

xlsx_read returns the same 501 capability_gap in one case: a read that recalculates (evaluate: true) on a workbook that uses the 1904 date system. Read the file without evaluate to get its saved values.

Prefer the MCP client?

If your agent speaks MCP, skip the HTTP wiring entirely — install the client and register it with two commands:

npm install -g xlsx-for-ai
claude mcp add xfa -- xlsx-for-ai-mcp

Full docs and the complete tool reference are on the GitHub repository and the npm package page.

Getting a file in and a result out

Two surfaces take a file in and give a result back: the MCP connector at https://api.xlsx-for-ai.dev/mcp, and the REST API at POST /api/v1/tools/<name>.

MCP connector: when Claude calls it

The connector’s server instructions open with four rules for when Claude should call it, led by links and by the jobs Claude’s own file tools cannot do. Claude reads them before it decides, word for word:

xlsx-for-ai is a spreadsheet engine with its own Excel-compatible calculator. Call it in these cases; do not work around it with a script. 1) The user gives a link to a spreadsheet (Google Sheets, Drive, Dropbox, OneDrive or another https link): pass it as file_url and the engine fetches it directly; do not download and parse it yourself. 2) The answer depends on what formulas evaluate to: call xlsx_eval. A file’s saved values can be missing or out of date, and re-deriving formulas by hand or in a script is unchecked work that can go wrong on dates, rounding, lookups and newer functions; xlsx_eval recalculates over 350 Excel functions, plus the functions only Google Sheets has, and says so when it cannot. 3) The user wants a workbook changed and handed back: xlsx_write edits the real file and keeps its formulas, styles, charts and names, which a rebuild from a script loses. 4) Large files (.xlsx up to 100 MB, .csv up to 200 MB), checking a workbook for errors and stale numbers (xlsx_check), a workbook health report (xlsx_doctor), or comparing two versions (xlsx_diff). The other tools read (xlsx_read, xlsx_list_sheets), convert (xlsx_convert) and clean (xlsx_data_clean) a file.

The file hand-off order below and the data-handling sentence follow it.

MCP connector: getting a file in

A chat host does not pass attached files to a connector, so the file reaches the tool one of three ways, in order of preference:

  1. A share link. Pass a Google Sheets, Google Drive, Dropbox or OneDrive share link, or another https link, as file_url. A Google Sheets link must be shared as “Anyone with the link” (Viewer): the server fetches Google’s own .xlsx export and cannot sign in to Google as you. If the sheet is not shared that way, the tool result says so and tells you to change the sharing or to download it as .xlsx and upload it.
  2. An upload page. If there is no link, call xlsx_upload_link. It returns a one-time upload page; you pick the file there, and the returned file_handle can be passed to any tool.
  3. The local package, for a large file on your own computer. The xlsx-for-ai npm package is an MCP server for desktop and coding clients. It reads from disk, so there is no browser upload. Its default limit is 50 MB, adjustable with XFA_MAX_FILE_MB.

When the AI’s sandbox has no network. A workbook is never sent as text: a text copy loses defined names, styles, merged cells and more, so answers on it could be wrong. If a tool receives a workbook as file_text, it computes nothing and replies with a fresh upload link. Show that link to the user; once they drop the real file in, call the tool again with the file_handle. Small CSV, TSV and JSON files can still be passed as file_text.

Reading a private Google Sheet through the live Google Sheets API (xlsx_read with source: "gsheets") needs a Google OAuth access token with the spreadsheets.readonly scope, supplied by the caller.

A link is read as the sheet stands at that moment, with Google’s calculated values. To recalculate after changing inputs, call xlsx_write with the workbook as the base plus the changed cells, then call xlsx_eval on the returned file_handle.

Paging a big link without fetching it again. When a link read with xlsx_read is cut (there is a next page), the server keeps the file it fetched and hands back a handle, so every later page reads the same copy: no second download, and no mixed versions if the sheet is edited while you page.

  • API: the reply carries _meta.cache_handle (with _meta.cache_handle_expires_at and _meta.cache_handle_size_bytes), and _meta.next_call already holds it. Send it as cache_handle, with options.offset, for each following page.
  • MCP connector: the same handle is returned as file_handle. Pass it as file_handle for each following page; the cut page’s next_call carries it.
  • Lifetime: the handle works like an uploaded file’s handle. It expires after one hour, only the client that made the read can use it, and it counts against that client’s storage quota. An expired or unknown handle is refused with 400; read the link again to start over, which returns the current version of the file.
  • When there is no handle: a read that fits on one page returns none, and nothing is kept when the request carries X-XFA-Privacy: strict or the key’s consent level is none.

Recalculating from a handle. xlsx_eval takes the same handle as its workbook source: send cache_handle on the API (file_handle on the MCP connector) with formulas and/or cells, and the answers match sending the file itself, without uploading it again. Send one workbook source only. An expired or unknown handle, or one from another key, is refused with 400 “cache_handle not found or expired”.

Typed results. Both tools can return real types instead of display text, chosen with options.value_format.

  • xlsx_eval: each evaluated cell comes back typed in _meta.cell_values: numbers as numbers, booleans, strings, and error codes. A date is a serial number plus its numFmt. value_format is "typed" by default for eval; send "text" for display text.
  • A blocked spill: when an array formula cannot spill because a cell in its way already holds a value or a formula, or the result would run off the sheet, the cells it would have filled keep their own content. The formula cell itself answers #SPILL! for Excel array functions; for the functions only Google Sheets has (FLATTEN, SPLIT, ARRAYFORMULA) it answers “not supported”. A blocked spill never returns the values it would have spilled.
  • xlsx_read: send options.value_format: "typed" (the default is "text") to get typed JSON rows: numbers, true/false, ISO dates, null for blanks, and long numbers and ids with leading zeros kept as exact strings. This also works when the read recalculates (evaluate: true, or formulas saved with no value): the rows carry the recalculated values, and a formula the engine cannot calculate yet is null and named in the row’s errors object as #UNSUPPORTED!.

Header row. With JSON output, options.header_row keys each row by its header text. Send true for row 1, a row number such as 3 when row 3 is the header (data starts on row 4), or "auto" to let the engine find the real header row in an export with a title row, blank rows or merged cells above it. It uses the same detector as xlsx_data_clean. The row used comes back in _meta.header_row_used. On json reads you can also send header_row: true to use row 1 as the header, header_row_number: N to use sheet row N (rows above it are left out and data starts on row N+1), or header_row_auto: true to pick the header row from the top 10 rows with the same scoring as xlsx_data_clean (row 1 if none stands out). _meta.header_row_used reports the row used, and offset and maxRows count data rows after the header. A header_row_number that points at a blank row is refused with a clear error. These work on the API and MCP, including Google Sheets reads. Keys are the header text exactly as written, and a duplicate gets a suffix (City_2).

Typed values with display text. Set options.value_format to "typed_with_text" (with format "json") and every cell comes back as {v, t, text}. v is the typed value, t its type (number, string, boolean, date, error or blank), and text is what Excel shows under the cell’s number format. For example {"v": 1234.5, "t": "number", "text": "1,234.50"}; a date shows as "2/28/1900", and an id like "00123" keeps its zeros. A CSV field’s text is the field exactly as written. Where the text can’t be shown exactly, text is left out and text_unavailable is true; it is never guessed. It works on plain, paged and cache_handle reads, over the API and MCP.

Per-cell formulas. xlsx_read with options.formulas: true returns formulas in any format, for the returned page only; pages taken with offset and maxRows do not overlap. In markdown (the default), each row that holds formulas is followed by a <row> formula line giving each formula, starting with =, in its own column. In SQL, each formula cell gets a comment after its row’s statement, for example -- formula D2: =A2+1. In JSON, formulas_by_cell maps each cell address to its formula text without the =. In markdown and SQL a backslash, a line break or (markdown only) a pipe inside a formula is written \\, \n, \r or \|.

Markdown cell values. Cell values are escaped in md output the same way, in xlsx_read, xlsx_read_handle and xlsx_convert to md: a backslash is written \\, a pipe \|, a line feed \n and a carriage return \r, so a value can never shift a column or start a new table row. Nothing is dropped, and a value without those characters is shown exactly as before.

MCP connector: getting a file back

Every tool that produces a file (xlsx_write, xlsx_convert, and the cleaning, redaction, repair, receipt and stamp tools) returns:

  • a download link in its result text;
  • an MCP resource_link content block;
  • _meta.download_url, _meta.download_expires_at, _meta.file_name and _meta.file_handle;
  • _meta.file_b64, which is still there.

The link is a signed, unguessable token. It works for about one hour, serves only the file of the account that produced it, and then returns 410. No copy is stored and no link is returned when the account’s consent level is none or the request carries the header x-xfa-privacy: strict. GET /download/<token> serves a file produced through the MCP door.

Exporting a Google Sheet to .xlsx

xlsx_convert with to: "xlsx" returns the workbook as Google exported it. Google Sheets functions that Excel does not support (for example QUERY, IMPORTRANGE, GOOGLEFINANCE and ARRAYFORMULA) do not stop the export. Those cells keep the value they had in the sheet and do not recalculate in Excel. The result carries a visible line starting “Google Sheets notice:” and a structured _meta.google_sheets_notice naming each function and where it is used. A workbook with none of them carries no notice.

Starter prompts

The connector offers eight starter prompts through MCP prompts/list. They show in the connector’s menu in Claude and as slash commands in Claude Code. Each one starts with the file hand-off above: it uses a link if you give one, and otherwise asks for an upload page link. The names are welcome, check_my_spreadsheet, recalculate_and_compare, read_exact_values, compare_two_versions, clean_my_data, write_xlsx_with_formulas and google_sheet_to_xlsx.

check_my_spreadsheet (“Check my spreadsheet for errors”) takes an optional file_url and runs xlsx_check on the workbook.

Choosing the tool list

tools/list returns every tool. The main tools come first, in this order: xlsx_read, xlsx_eval, xlsx_write, xlsx_convert, xlsx_list_sheets, xlsx_upload_link. The rest follow by name. A client that wants a short list can send the header x-xfa-toolset: core or connect to /mcp?toolset=core. Every tool stays callable by name.

The npm client

The current npm package is xlsx-for-ai 4.3.0 (npm install -g xlsx-for-ai@latest). It reads the tool list from the service each time it starts, so it offers the 78 tools the service lists today: the 54 public-stable tools, the two session tools, and the Shopify, catalog and Importable tools. A copy bundled in the package covers a start with no network. Each tool's own arguments are sent to the service as given.

xlsx_pii_clean and xlsx_vault_cure need a selection, or the service answers clean_selection_required. For xlsx_pii_clean it is {"type_keys":["ssn_us"]}, {"finding_ids":[...]} or {"all":true}; {} changes nothing. For xlsx_vault_cure it is {"risk_tiers":["high"]} or {"finding_ids":[...]}; {} cleans only what is handled automatically.

shopify_ebay_feed needs a category_map (each product type to an eBay category_id and condition_id) and these options: dispatch_time_max (whole days, for example "3"), location, returns_accepted_option and shipping_type. duration (default GTC) and format (default FixedPrice) are optional.

REST API

The REST API is unchanged. Send file_b64 to POST /api/v1/tools/<name> and receive produced bytes in _meta.file_b64.

REST API: sending a big file in chunks, and resuming

With a key, a big file can go up in chunks. Pick a handle, then send each chunk to POST /api/v1/cache/upload-chunk as {"handle", "chunk_index", "total_chunks", "chunk_b64"}, with chunk_index from 0. Each reply is {"handle", "received", "total", "complete", "received_indices"}. received_indices is the sorted list of chunk indices stored so far. When complete is true, call POST /api/v1/cache/finalize with {"handle"} and pass the handle to any tool.

  • Resuming after a dropped connection: send any chunk again, or read the last reply, then resend only the indices missing from received_indices.
  • Sending a chunk twice: the same bytes again are accepted (200) and change nothing. Different bytes for an index already stored are refused with 409 chunk_mismatch, and nothing is written.
  • Lifetime: an unfinished upload is kept for 30 minutes after its last chunk.

Scanning for personal data without waiting for names and addresses

xlsx_pii_scan normally waits for its name and address check. An app that scans on every save can send "ner": "deferred" (REST POST /api/v1/tools/xlsx_pii_scan, or the same argument on MCP). The answer then comes back at once with every other finding, plus _meta.ner_status and _meta.ner_job_id. The fast answer does not include names and addresses until the job is done.

  • ner_status: "done", ner_job_id: null: nothing needed checking; this is the full answer.
  • ner_status: "pending": fetch the names and addresses with xlsx_pii_job_status and {"ner_job_id"} (REST POST /api/v1/tools/xlsx_pii_job_status, or the MCP tool) before you share, export or copy the file. It answers pending, done (the findings, in the scan’s finding shape without an excerpt) or failed (a plain reason; scan again).
  • Privacy: only the account that ran the scan can read its job. Results are kept 60 minutes after the scan and hold no cell text. Polls do not count against your monthly calls.

Without ner, nothing changes: the scan waits and returns everything in one answer.

Formula cells with a saved value

In xlsx_write, a cell can carry both formula and value, for example {"address": "A1", "formula": "1+2", "value": 3}. The value is written as the formula's saved result, so the file opens in Excel showing it without recalculating. The reply's _meta.cached_formula_cells counts the formula cells written with a value; through the MCP connector the reply says "N formula cells with a cached value". The value must be a number, text or TRUE/FALSE; any other value on a formula cell is refused with 400 bad_request. Style on a formula cell is written too.

Resumable uploads

An app can send its user’s file straight to xlsx-for-ai through a one-time upload link, in one request or in parts that resume after a dropped connection.

Get a link

POST /api/v1/tools/xlsx_upload_link with your API key (Authorization: Bearer <api_key>). The body is optional JSON with one field, purpose, a short note of up to 200 characters shown on the upload page. Minting stores no file and does not count against your allowance; the file counts when a tool processes it.

curl -sS -X POST https://api.xlsx-for-ai.dev/api/v1/tools/xlsx_upload_link \
  -H "Authorization: Bearer $XFA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"purpose":"Q3 sales workbook"}'

The reply is { "content": [{ "type": "text", "text": "..." }], "_meta": { "upload_url", "file_handle", "expires_at" } }. The text is the how-to for the link. _meta.upload_url is the link, _meta.file_handle is the handle to pass to any tool once the file has arrived (cache_handle on the API), and _meta.expires_at is when the link expires, 30 minutes after it was made. Only the key that made the link can use its handle.

Send the file

  • One request. PUT the whole file to the link. This works exactly as before.
  • In parts. PUT each part to the link with the header Content-Range: bytes <first>-<last>/<total>, for example Content-Range: bytes 0-16777215/52428800. Any part size works; send the parts in order. The first part fixes the total size. A part that repeats bytes already received is accepted when the bytes are identical.
  • Resuming. HEAD the link. The reply carries Upload-Offset, the number of bytes received so far. Send the rest from that offset. A part cut off by a dropped connection keeps the bytes that arrived.
curl -sS -I "$UPLOAD_URL"   # reads Upload-Offset
curl -sS -X PUT -H "Content-Range: bytes 0-16777215/52428800" \
  --data-binary @part1 "$UPLOAD_URL"

Each part’s reply is { "ok": true, "complete": false, "offset": <bytes received>, "total": <total> } with the Upload-Offset header. The upload finishes when the last byte arrives: that reply has "complete": true, and file_handle then works with every tool, the same as after a one-request upload.

Errors

  • 416 range_gap: the part starts past the bytes received. The reply carries Upload-Offset; resend from there.
  • 409 range_mismatch: bytes already received differ from the bytes you sent. Nothing is written.
  • 409 total_mismatch: the total size differs from the one the first part declared.
  • 409 upload_incomplete: some received bytes were lost before the upload finished. The reply carries the true Upload-Offset; resend from there.
  • 409 upload_in_progress: a whole-file PUT was sent while parts are still arriving.
  • 410: the link expired before any part arrived, or the partial upload expired. Ask for a new link.

How long it is kept

A partial upload is kept for 30 minutes from the last part. While it is kept, the link keeps taking parts and answering HEAD, even after the link’s own 30 minutes.
