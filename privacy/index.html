Privacy

Last updated: 2026-10-18

A file is held until its upload handle or download link expires (60 minutes; an edit session up to 4 hours). No debugging copy is kept; logs and error reports carry no file contents; no training use.

This policy explains how xlsx-for-ai handles your data. It covers the hosted API at api.xlsx-for-ai.dev, the xlsx-for-ai connector for Claude (MCP), the Claude Code plugin, the npm client, this website, and the paid plans (together, the "Service"). It is written for developers who want to audit the data flow before deploying xlsx-for-ai in an agent, and for FP&A teams who need to forward it to legal before using an agent that touches financial spreadsheets.

Who we are

The Service is provided by Fremen Works ("we", "us"). Fremen Works is the controller of the account, billing, and log data described below. For the contents of the files you send, we process them only to run the tool you called, on your instruction. Questions, data requests, and security reports all go to support@xlsx-for-ai.dev.

Architecture

xlsx-for-ai is a hosted spreadsheet engine. The connector, the plugin, the npm client, and direct API calls all send the file to the xlsx-for-ai API over HTTPS. The server processes it and returns the result to your agent or program.

This means: workbook bytes leave your machine and travel to our server for every tool call. If that is not acceptable for your threat model, do not send that file to the Service.

Data we collect

When you sign in

The connector and the paid plans use Google sign-in. From Google we receive and keep your verified email address, and nothing else from your Google profile: no name, no picture. The email is stored encrypted (AES-256-GCM), with a keyed hash used to look it up. Your account is linked to sign-in records of our own, also stored encrypted. Sign-in tokens are short-lived: an access token lasts 10 minutes and a refresh token lasts 30 days without use.

API keys

We store each API key only as a keyed hash plus a short display prefix, so we can recognize a key without keeping the key itself. A key is shown to you once, when it is issued.

Anonymous client registration

The npm client can register without any sign-in. On first run it generates a random UUID (the client_id) locally and sends it to POST /api/v1/clients with your platform and client version. The server returns an API key. Both are stored in ~/.xlsx-for-ai/config.json. No email address, phone number, or name is asked for on this path. To drop that registration, remove the config file:

rm ~/.xlsx-for-ai/config.json

The next tool call will register a new client. Usage records for the old client_id stay under that id until they age out (see Retention).

What each tool call sends

  • File bytes, for the file your agent asked to process.
  • Your API key or sign-in token, which identifies your account or client_id.
  • Platform and version, for example darwin-arm64, 2.0.0, used for compatibility.
  • Tool name and options, meaning which tool you called and the parameters you passed (sheet name, format, and so on).

The npm client sends file bytes only, never the file's local name or path.

Usage and security records

We log the following per request: timestamp, client_id, endpoint, response status, file size (bytes), sheet count, structural fingerprints (formula count, sheet dimensions, built-in function names, feature flags like "uses_LAMBDA"), error class and error literal type (if any, for example #DIV/0!), latency, and which hardening checks ran. We do not log cell values, formula text, row data, file names, or any representation of workbook content.

IP addresses: for requests without an account, the request record holds a one-way hash of the IP address made with a random salt that changes every day, and no hash at all when the request carries X-XFA-Privacy: strict. Security events (a sign-in, a failed authentication) are recorded with the IP address they came from. Rate limiting uses the IP address for short time windows of up to an hour.

Payment data

Paid plans are bought through a hosted checkout run by our payment processor. Your card details go to the processor and never reach our servers. We keep the processor's customer and subscription identifiers, the plan, its status, and its billing period. When we store a billing event the processor sends us, we first remove the payer's name, email, phone, address, tax ID, and card or payment-method details.

Support messages

If you write to us or send feedback, we keep what you send, including the email address you write from, to answer you.

Cookies and the website

This website sets no cookies and runs no scripts. The sign-in pages set only the cookies the sign-in itself needs. We use no advertising or product-analytics tools.

What happens to the file bytes

File bytes are processed for your request. The only copies of your file are the short-lived ones below, each of which expires automatically when its time runs out. No workbook is captured for debugging or any other purpose, whether a request succeeds or fails.

Download linkA tool produces a file for you to fetch. A link serves only the account that produced it.60 minutes

In-memory parse cacheA repeat call on the same file within minutes5 minutes, held in memory only

When the account's consent level is none or the request carries X-XFA-Privacy: strict, no download copy is kept and no download link is issued, cache handles are cut to 60 seconds, and the in-memory parse cache is skipped. Use the CLI flag --privacy=strict to add this header to every request from a CLI session, or set the environment variable XFA_PRIVACY=strict.

No capture. We do not keep copies of workbooks, redacted or not, when a request fails or succeeds. Error reports sent to our error tracker carry the error type and our own code's stack trace, never the error message text, because that text could contain values from your file.

No training. Your files and their contents are not used to train models.

When part of a file goes to an AI model. A few tools ask an AI model (Anthropic's Claude API) for help, and send it only the part of the file that job needs:

  • xlsx_pii_scan and xlsx_redact send short candidate text strings from the file, as they appear in it, to find names and addresses. With X-XFA-Privacy: strict, xlsx_redact skips the model.
  • The Shopify import tools and the import converter send the column headers and a few sample values from each column, to match columns to the target format. The sample values are masked first: every letter becomes X or x and every digit becomes 0, so only the shape of the value is sent.

No other tool sends file contents to anyone. Tools you point at a destination, such as xlsx_post_slack or xlsx_post_teams, send what you ask them to send.

No local fallback

The client has no local parsing path. Every tool, including xlsx_read, sends the file to the API for processing. If the API is unreachable, the call fails with an error rather than reading the file on your machine.

Telemetry

Client telemetry in the npm client is opt-in and disabled by default. When enabled, we capture aggregate usage signals (call counts, error rates, file size distributions) tied to your client_id. No workbook content is captured in telemetry.

xlsx-for-ai --enable-telemetry    # opt in
xlsx-for-ai --disable-telemetry   # opt out (default)
xlsx-for-ai --telemetry-status    # check current setting

The telemetry setting is stored in ~/.xlsx-for-ai/config.json under the telemetry key. It persists across upgrades.

Why we use your data, and our legal bases

  • To run the Service: processing your files, signing you in, checking your API key, counting files against your plan, and taking payment. Legal basis: performing our contract with you.
  • To keep the Service secure and working: rate limiting, preventing abuse, investigating errors, and measuring which spreadsheet features need work, using the request and security records above. Legal basis: our legitimate interest in a secure, reliable service; these records carry no workbook content.
  • To meet legal duties, such as keeping billing records. Legal basis: legal obligation.
  • Client telemetry, only if you turn it on. Legal basis: your consent, which you can withdraw with --disable-telemetry.

We do not sell your personal information, and we do not share it for cross-context behavioral advertising. We do not send you marketing email.

Retention

  • Files: as in the table above, from 5 minutes to at most 24 hours, depending on the copy.
  • Request records (request metadata, not workbook content): 90 days, then deleted.
  • Security event records, including the IP address of each sign-in or failed authentication: 365 days, then deleted, unless needed for a legal claim.
  • Account and billing records (your encrypted sign-in email, plan, and subscription identifiers): while your account exists, and afterwards as long as the law requires for billing records.
  • Backups: database backups are encrypted before they leave the server and are rotated out on a schedule, so a deleted record can remain in a backup for a limited time before it ages out.

We will update this page if a retention period changes.

Who we share data with

We share personal data only with service providers that help us run the Service (hosting, sign-in, payment processing, error tracking, and the AI model use described above), only as needed for that service, or when the law requires it. Each of them handles the data for us, not for its own marketing. We do not sell personal data to anyone.

International transfers

We and our service providers may process your data in the United States and in other countries, which may have data-protection laws different from those where you live. Where the law requires a safeguard for such a transfer, such as standard contractual clauses, we rely on one.

Security

All traffic to the Service is encrypted in transit with TLS. API keys are kept only as keyed hashes. Sign-in identity data, including your email, is encrypted with AES-256-GCM before it is stored. Database backups are encrypted before they leave the server. Access to production systems is limited to Fremen Works administrators and our automated deployment system.

Compliance posture. xlsx-for-ai is not SOC 2 certified. It is not HIPAA- or PCI-certified. Do not use it to process protected health information or payment card data in regulated environments without additional controls.

If there is a breach. If we confirm a breach of personal data we hold about you, we will notify you and, where the law requires, the regulator, without undue delay and within the time the law sets.

Your rights

Depending on where you live, including under the EU and UK GDPR and the California Consumer Privacy Act as amended by the CPRA, you may have the right to know what personal data we hold about you, to get a copy of it, to correct it, to delete it, to object to or restrict how we use it, to withdraw consent you gave, and not to be treated differently for using these rights. In the EU or UK you may also complain to your data-protection authority.

To make a request, email support@xlsx-for-ai.dev with "privacy request" in the subject line. Write from the email address you sign in with, or include your client_id (found in ~/.xlsx-for-ai/config.json) if you never signed in. We may need to confirm the request is yours. We answer within 30 days. An authorized agent may make a request for you with your written permission.

The anonymous client_id is not linked to a name or email. If you believe one is linked to you and want its records deleted, tell us the client_id and we will delete all records for it within 30 days.

Children

The Service is not directed to children under 13, and we do not knowingly collect personal data from them. If you believe a child under 13 has given us personal data, email us and we will delete it.

Consent level

Workbook capture is off for every account, whatever its consent level. The consent level now controls one thing. Setting it to none through PATCH /api/v1/clients/me/consent is the same as sending X-XFA-Privacy: strict on every request: no download copies, 60-second cache handles, and no in-memory parse cache.

Changes to this policy

If we change how we handle personal data, we will update this page and its date before the change takes effect. For a material change, we will also say so on this page.
