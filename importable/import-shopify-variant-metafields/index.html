What it does

Per-SKU data — chest and waist measurements that change with every size, fabric content that changes with every colorway, a care code per variant — naturally lives one row per SKU, one column per field. Shopify writes metafields one at a time, keyed by owner, namespace and key. This tool does the conversion: it reads your SKU column and every column named Variant Metafield: <namespace>.<key> and writes one import row per SKU and metafield, with the type you declared in square brackets.

Name your columns and we'll read them

A metafield column is Variant Metafield: custom.chest_cm [number_decimal] — the namespace and key exactly as they appear in your Shopify metafield definitions, and the type in square brackets. Leave the brackets off and the values are carried as text. Your SKU column can be called Variant SKU or just SKU.

It flags what it won't write

A column we can't place, a product-level metafield in a variant-level file, a type Shopify doesn't recognise, two columns claiming the same metafield, a row with values but no SKU — none of those are guessed at. They're held back and listed under what needs you, with the reason. Everything we did map shows up under what we mapped, so every column in your file is accounted for.

Blank cells never clear a metafield

An empty cell produces no import row at all, and every row we write is a merge — it creates the metafield if it's missing and updates it if it's there. Nothing in the file you upload can turn into an instruction to erase a value you already have.

Reviewed file, not an automatic write

This tool hands you a reviewed file to check and import yourself — it never writes to your store directly. Your uploaded file is read in memory and never stored.
