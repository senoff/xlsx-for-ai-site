Free · works with your assistant

Check your AI's spreadsheet work.

AI assistants are good at spreadsheets — and confidently wrong just often enough to matter. xlsx_check re-computes every formula in a workbook with an independent engine and compares the results against what the file claims, then reports what it finds. Add it to your assistant's tools and it checks its own work: build the workbook, run the check, fix what it catches, and hand you a verified, stamped file.

Free · no signup · runs on your machine

This is a two-minute, one-time setup. Pick your assistant below, paste one config block, and xlsx_check and csv_check show up as tools your assistant can call on any .xlsx or .csv file.

How it works

1

Add one config snippet

Register the xfa MCP server in your assistant — the block for your specific client is below. One time, then you're done.

2

Your assistant checks its own work

After it edits a workbook, it calls xlsx_check — a second, independent engine recomputes every formula and flags anything that disagrees.

3

Findings, fixes, and a stamp

You get exact cells and suggested fixes. A clean file gets a verifiable stamp inside it, so anyone downstream can confirm it wasn't altered.

First, install the server (once)

Every snippet below registers a local MCP server named xfa. Install it with npm (needs Node 18+):

npm install -g xlsx-for-ai

That puts the xlsx-for-ai-mcp command on your PATH. Prefer not to install globally? Replace "command": "xlsx-for-ai-mcp" with "command": "npx", "args": ["-y", "xlsx-for-ai-mcp"] in any config below.

Set it up: desktop & CLI assistants

Every snippet here was verified against that client's current MCP documentation on 2026-08-17. Each registers the same server under the name xfa.

Claude Desktop

Config: ~/Library/Application Support/Claude/claude_desktop_config.json (macOS) · %APPDATA%\Claude\claude_desktop_config.json (Windows). Settings → Developer → Edit Config, then restart Claude.

{
  "mcpServers": {
    "xfa": {
      "command": "xlsx-for-ai-mcp"
    }
  }
}

Claude Code

One command in your terminal (writes to ~/.claude.json; add --scope user for all projects):

claude mcp add xfa -- xlsx-for-ai-mcp

Cursor

Config: .cursor/mcp.json (this project) or ~/.cursor/mcp.json (all workspaces). Enable it under Settings → Tools & MCP.

{
  "mcpServers": {
    "xfa": {
      "command": "xlsx-for-ai-mcp"
    }
  }
}

VS Code (GitHub Copilot)

Config: .vscode/mcp.json (workspace) or the MCP: Open User Configuration command. Note VS Code's key is servers and each entry needs an explicit "type": "stdio".

{

    "xfa": {
      "type": "stdio",
      "command": "xlsx-for-ai-mcp"

  }
}

Set it up: open & local harnesses

Run any model — Llama, Mistral, Qwen, DeepSeek, GLM, Kimi — through one of these harnesses and xlsx_check works the same way. The config lives with the harness, not the model. All snippets verified 2026-08-17.

Cline (excel MCP for VS Code)

Open the Cline panel → MCP Servers icon → Configure → Configure MCP Servers (this opens cline_mcp_settings.json).

{
  "mcpServers": {
    "xfa": {
      "command": "xlsx-for-ai-mcp",
      "args": [],
      "disabled": false,
      "autoApprove": []
    }
  }
}

Roo Code

Config: .roo/mcp.json (project, recommended) or the global mcp_settings.json via the Roo Code MCP panel → Edit Global MCP.

{
  "mcpServers": {
    "xfa": {
      "command": "xlsx-for-ai-mcp",
      "args": [],
      "disabled": false,
      "alwaysAllow": []
    }
  }
}

Continue.dev

Add a block file at .continue/mcpServers/xfa.yaml in your workspace (reload the window afterward). Continue's mcpServers is a YAML list.

name: xlsx-for-ai
version: 0.0.1
schema: v1
mcpServers:
  - name: xfa
    type: stdio
    command: xlsx-for-ai-mcp

Goose

Fastest: goose configure → Add Extension → Command-line Extension (name xfa, command xlsx-for-ai-mcp). Or edit ~/.config/goose/config.yaml:

extensions:
  xfa:
    name: xfa
    cmd: xlsx-for-ai-mcp
    args: []
    enabled: true
    type: stdio
    timeout: 300
    envs: {}

LM Studio

Program tab → Install → Edit mcp.json (file at ~/.lmstudio/mcp.json). Use the in-app button — the path varies by install.

LibreChat

Add to librechat.yaml under the top-level mcpServers: key:

  xfa:
    type: stdio

Open WebUI

Open WebUI speaks MCP over HTTP, so bridge the local server with mcpo, then register the endpoint under Admin Settings → Integrations:

uvx mcpo --port 8000 -- xlsx-for-ai-mcp

Then add http://localhost:8000 as a tool server in Open WebUI.

Ollama

Ollama itself has no MCP support — it's a model server. Pair it with a harness that does: point Continue.dev (above) at your local Ollama model and add the xfa server there, or run Open WebUI against Ollama with the mcpo bridge above.

Hosted assistants that connect by URL

Some assistants connect only to remote MCP servers reached over a public URL — they can't launch a local command. xlsx_check runs as a local server, so the simplest path today is to use one of the desktop or CLI clients above. For these, here's the honest state as of 2026-08-17:

ChatGPT

Remote MCP only. ChatGPT's Developer mode / MCP apps connect to a server over a public URL; there's no field for a local command. To use it there you'd expose the server over HTTPS yourself (OpenAI's Secure MCP Tunnel). Until then, run the check in Claude, Cursor, VS Code, or any CLI client above. See ChatGPT's MCP docs.

Grok

Remote MCP only. Grok's "bring your own MCP" connectors take a public server URL, not a local binary. Use a desktop/CLI client above today, or expose the server over HTTPS via a tunnel. See Grok's connector docs.

Mistral Le Chat

Remote MCP only. Le Chat's Custom MCP Connector accepts an HTTPS server URL, not a local command. Run xlsx_check through a local client above, or stand up a remote MCP endpoint. See Le Chat's MCP docs.

DeepSeek & Qwen Chat (web)

DeepSeek's app isn't an MCP host, and Qwen's web chat currently adds remote (URL) MCP servers only. To check spreadsheets with these models, run them inside a harness that speaks stdio MCP — Qwen Code for Qwen, or any harness in the section above with DeepSeek as the backend model.

What it catches

xlsx_check recomputes the whole workbook through a second, dissimilar engine and compares — so it catches the errors that don't announce themselves. Three of the classes it flags:

#REF!

Broken references

A formula points at a cell, column, or sheet that was deleted or moved — e.g. =SUM(Sheet2!B2:B40) after Sheet2 was renamed. Reported with the exact cell and the error token, as a BLOCKER.

MISSED ROW

A range that silently misses the last row

The total looks fine but stops short of the data: =SUM(B2:B41) over a column that runs to B42. No error token, wrong answer. Flagged as a WARN with the exact extended range as the suggested fix.

STALE VALUE

Stale cached values that look right and aren't

The file stores 1,240 for a cell whose formula now computes 1,318 — a value that was correct when last saved and isn't now. The independent recompute catches the disagreement and reports it as a WARN.

It also runs an error-cell census (#DIV/0!, #NAME?, #VALUE! …) and a hygiene pass (macros, external links, hidden sheets). csv_check covers CSV files: parse validity, ragged rows, encoding anomalies, and a formula-injection lens.

The stamp

When a file comes back clean, xlsx_check can embed a signed receipt inside it — a stamp. It travels with the file: forward the workbook to anyone, and they can run xlsx_verify_stamp to confirm it passed the check and wasn't altered afterward. The stamp is the object that travels inside a verified file, so a reviewer downstream doesn't have to take the sender's word for it.

FAQ

Is it free?

Yes. Every check is free — there's no billing gate on xlsx_check or csv_check. A volume cap keeps the hosted API healthy; that's the only limit.

Does it change my file?

No. A check reads the workbook and reports — it changes nothing on its own. Your assistant fixes what it catches and shows you the change. The one exception is when you ask for a stamp: that writes a signed receipt into a clean copy (a Save-As), which is the point.

What data is sent, and who can see it?

The MCP server runs locally, on your machine — your spreadsheet is parsed there. The hosted API uses anonymous UUID registration: no email, no name. A per-request strict mode disables any error capture. Read the privacy policy.

Which assistants does it work with?

Any assistant that speaks the Model Context Protocol over stdio — that's the whole desktop & CLI and open harness list above. Assistants that only connect to remote MCP servers by URL are covered here.

Do I need to write any code?

No. Install once (npm install -g xlsx-for-ai), paste one config block for your assistant, and ask it in plain English to check your spreadsheet.
