Shopify theme display · plain-language explainer

You set up a metafield, entered the values — and nothing shows on the product page.

You are not doing it wrong, and the data is almost certainly fine. Storing a metafield value and showing it are two separate acts in Shopify, and only the first one happens in the admin. The second happens in your theme, and it does not happen by itself.

There are four reasons a correctly-filled metafield stays invisible. This page names all four, tells you how to work out which one is yours in about a minute, and walks the real fix for each — in the theme editor, in plain language.

Explainer · nothing to upload · nothing to install

The one thing nobody says out loud

In Shopify, a metafield is storage. You create a definition under Settings → Custom data, you type a value into it on a product, and that value is now saved against that product. Every part of that is finished and correct — and none of it puts a single pixel on your storefront.

Displaying it is a second, separate job that belongs to your theme. Somewhere in the product template, something has to say “print the value of custom.material here.” Until something says that, the value sits in the database being perfectly correct and completely invisible. Shopify does not warn you about this, because from its point of view nothing has gone wrong.

So the question is never “why is my metafield broken?” It is: why can't my theme print it? There are four answers.

Sixty-second triage: which of the four is yours?

Open Online Store → Themes → Customize. In the dropdown at the top of the editor, switch from the home page to Products → Default product. Now look:

  • There is no “Add block” anywhere under the product information area, and the left panel only really lets you change colours and fonts. Your theme is vintage — that is cause 1.
  • You can add blocks, you added one, and the little dynamic-source icon next to its text field doesn't list your metafield. The block's type and the metafield's type don't match — cause 2 — unless the metafield is a URL, which is cause 4.
  • You added the block, you connected the metafield, the editor shows no error, and the block renders as nothing at all. The metafield is almost certainly empty on the product you're looking at — cause 3.

Shopify changes the theme editor regularly and themes differ in what they name things. The wording below describes what most merchants see today; if your theme labels a panel differently, the mechanic underneath is still the same.

Cause 1 — your theme is vintage (not Online Store 2.0)

This is the most common cause and the most frustrating one, because nothing about it looks like an error. Themes built before Online Store 2.0 have no dynamic sources at all. There is no connector, no metafield picker, no “insert dynamic source” icon anywhere in the editor — the feature that binds a metafield to a block simply does not exist in that theme. You can create a hundred perfect metafield definitions and a vintage theme will never offer you one.

How to confirm it. In Customize, switch the top dropdown to Products → Default product. An Online Store 2.0 theme lets you add and reorder blocks inside the product information section, and the settings for those blocks have a small dynamic-source icon beside them. A vintage theme gives you a fixed product page you can style but not restructure: no block list, no Add block, no connector icon. If you never see that icon on any setting, that is your answer.

What actually fixes it. Two honest options, and they are genuinely different sizes of job:

  • Move to an Online Store 2.0 theme. Every theme in the Shopify Theme Store today is OS 2.0. This is the option that gets you a metafield on the page without anyone writing code — but it is a theme change, so treat it like one: install the new theme as an unpublished draft, rebuild your pages in it, and preview thoroughly before you publish. Nothing about your metafield data is affected either way; it is stored against your products, not against your theme.
  • Have a developer add the Liquid. A vintage theme can still print a metafield if someone edits the product template directly and adds the line that outputs it. That is a code change in your theme files, and it is a developer's job — we are not going to walk you through writing Liquid on this page, because a half-explained theme edit is how storefronts break. If you have a developer, this is a small task for them: they need to know the metafield's namespace and key (from Settings → Custom data) and where on the page you want it.

Cause 2 — the block you added can't hold that kind of metafield

You're on an OS 2.0 theme, you hit Add block, and you picked Text because text is what you want. Then you clicked the dynamic-source icon on its content field and your metafield wasn't in the list — or a different metafield was, but not the one you wanted.

That list is filtered. The theme editor only offers you metafields whose type the setting can actually render. A text setting will show you text metafields. It will not show you a file, an image, a product reference, or in many themes a list-typed metafield, because a text setting has no idea what to do with any of those. Nothing is broken; the picker is refusing to connect two things that don't fit together, and it does that silently by just not listing them.

The mismatch, concretely. The type you chose in Settings → Custom data decides which blocks can display it:

  • Single line text or Multi-line text → a Text block, or the theme's own metafield/custom-content block. This is the easy case.
  • Rich text → a Text or rich-text block. Themes vary in how much of the formatting they honour.
  • File or Image → an Image block, not a Text block. A text setting will never list a file metafield.
  • Any list. type (a list of text values, a list of products) → a block or section that is built to iterate a list. A plain text setting usually won't take one, and this catches people out constantly, because list.single_line_text_field feels like it should just be text.
  • Product, file or metaobject references → these point at another object rather than holding a value, so they need a block designed for that object — a related-products or featured-collection style block, not a text field.

What actually fixes it. Either add the block that matches the type — delete the Text block, add an Image block for an image metafield — or, if what you really wanted was text all along, change the definition's type in Settings → Custom data to a text type and re-enter the values. Changing a definition's type is not free: Shopify will not silently convert your existing values, so plan on re-entering them. Many themes also ship a general-purpose Metafield or Custom content block precisely for this; check your theme's block list before you conclude the type is wrong.

Cause 3 — it's connected, there's no error, and it still renders nothing

This one feels like the worst of the four and is nearly always the easiest. An OS 2.0 theme, the block is there, the dynamic source is connected, the editor is perfectly happy — and the product page shows an empty gap where your text should be.

A dynamic source that resolves to an empty value renders nothing. Not a placeholder, not an error, not a warning: nothing. It looks identical to a broken binding, but the binding is fine. The metafield has no value on that particular product.

How to confirm it, in order:

  1. Check which product you're previewing. The theme editor previews one specific product, and by default it's whichever one it picked — not necessarily the one you filled in. Use the product selector at the top of the editor to preview a product you know has a value.
  2. Open that product in the admin. Products → the product → scroll to the bottom. The Metafields card lists the definitions that apply to it; click through to see all of them. An empty field here is your answer.
  3. Check it's the same definition. If you have two similar definitions — say custom.material and custom.materials, or one you made and one an app made — it is very easy to fill in one and bind the other. Compare the namespace and key on the product against the one the block is connected to.
  4. Check the value is on the product, not the variant. Product metafields and variant metafields are different fields with different owners. A value entered on a variant will not appear in a block bound to the product-level metafield, and the reverse is equally true.

If the value really is missing on most of your products, that is a data-entry problem rather than a display problem, and it's the one place where a spreadsheet is genuinely the right tool — see below for where that line sits.

Cause 4 — it's a URL-type metafield

URL metafields are a real, current gap. If you defined a metafield with the URL type, the theme editor's dynamic-source picker generally will not offer it on a standard block — not on text settings (a URL isn't text as far as the picker is concerned) and not reliably on link settings either. You can spend a long time hunting for the block that takes it, and the honest answer is that there usually isn't one.

This is a platform limitation, not something you've misconfigured, and it is the one cause on this page where no amount of clicking in the theme editor will get you there.

The two real ways out:

  • Use a different type, if a URL isn't strictly required. If what you actually want is a visible link, a rich text metafield holding a hyperlink is bindable in most themes and renders as a working link. If you just need the address shown, single line text works and displays fine. Both mean redefining the field and re-entering the values — Shopify won't convert them for you — so it is worth deciding this before you have five hundred products filled in.
  • Have a developer output it in Liquid. A URL metafield is perfectly readable from theme code; it's only the no-code connector that can't reach it. A developer can add a short snippet to the product template that prints it as a link. Again, this is a theme code change and a developer's task, and we are deliberately not walking you through it here.

Shopify does change what dynamic sources accept. If you are reading this some time after it was written, it is worth re-opening the picker and checking before you redefine anything.

What this page is — and what it isn't

This is an explainer. We build spreadsheet-to-Shopify import tools, and it is worth being blunt about the boundary, because it is the exact thing a page like this could be tempted to blur.

An import tool writes metafield values — it puts data into the fields you defined, in bulk, from a spreadsheet. Whether those values then appear on your storefront is decided entirely by your theme, and nothing outside your theme can change that. No import tool, ours included, can make a metafield appear on a product page. If your theme has no dynamic source connected to that metafield, the value will be sitting there perfectly stored and just as invisible after any import as before it.

So there is nothing to upload on this page, and no tool of ours to point you at for this problem. The four fixes above happen in your theme editor or in your theme's code, and that is where they have to happen. We'd rather say that clearly than sell you a step that wouldn't help.

Where a spreadsheet does help: getting the values in

The one thing on this list a spreadsheet solves is cause 3 at scale — the metafield is bound correctly but empty across a lot of products. Filling hundreds of metafields by hand in the admin is the work people avoid, which is why so many definitions sit empty. These pages are about that half of the problem, and only that half:

  • Bulk-upload product metafields — material, care, sizing, ingredients and specs from the product sheet you already keep, without renaming your columns to match a template.
  • Bulk-edit variant metafields — per-SKU values that Shopify's own CSV import ignores entirely, with no error.
  • Reference & file metafields — the exact working format for product references, file references and metaobject references, the same types that cause block mismatches above.
  • Safe metafields re-import — what your edited export would actually do before you upload it, including the blank cells that wipe values and the type changes that get rejected.
  • Metafield references across stores — why cloning or migrating a store nulls every reference metafield, and the handle-based fix.

Every one of those is about getting correct values into your metafields. None of them touches your theme, and none of them changes what your product page renders.

Quick recap

  • No connector icon anywhere in the theme editor → vintage theme. Move to an Online Store 2.0 theme, or have a developer add the Liquid.
  • Connector icon exists, your metafield isn't in its list → block type and metafield type don't match. Use the block that fits the type, or change the type.
  • Connected, no error, renders nothing → the metafield is empty on the product you're previewing, or you filled in a different definition, or you put the value on the variant instead of the product.
  • It's a URL metafield → the picker can't reach it. Use rich text or plain text instead, or have a developer print it in Liquid.
