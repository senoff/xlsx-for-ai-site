A PivotTable report cannot overlap another PivotTable report

You try to refresh, move, or drop a new pivot table onto a sheet and Excel stops you cold: “A PivotTable report cannot overlap another PivotTable report.” It doesn't say which pivot, or where the collision is. Drop the file in below to see every pivot's range and the data behind it instead.

What this looks like

You click Refresh, drag a pivot table to a new spot, or paste a new pivot near an existing one, and Excel throws “A PivotTable report cannot overlap another PivotTable report” and refuses to complete the action. The refresh or move doesn't partially apply — it just fails, and the dialog gives you no cell reference or pivot name to go check.

Why it happens

Every pivot table reserves a rectangular output range on its sheet, and Excel enforces a strict no-overlap rule between reserved ranges so it can safely rebuild a pivot's layout on refresh without clobbering a neighbor. The range a pivot reserves isn't just its current visible size — it accounts for how the report could grow. Two pivots that looked fine side by side can collide the moment either one's data grows, a sheet gets copied and duplicates a pivot definition, or someone drags a pivot a few rows closer to another.

What you actually want

Not to guess at cell boundaries inside Excel — you want to see where each pivot table actually sits, what source range and data it's built from, and its row/column/value field layout, so you can diagnose or rebuild it deliberately. xlsx-for-ai reads pivot table definitions directly out of the file — their source range, cached layout, and field structure — without running Excel's pivot engine, so an overlap that blocks Excel doesn't block you from seeing what each pivot was built from and where it actually sits.
