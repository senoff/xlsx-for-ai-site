Why validate across two engines?

An .xlsx file is a zipped bundle of XML, and different spreadsheet libraries are stricter or more forgiving about how they read it. A workbook can open perfectly in the app that wrote it and then lose a sheet, drop a row, or misread a cell in the next tool that touches it — an importer, a data pipeline, or a coworker on different software. Reading the file through two independent engines and diffing the result surfaces exactly those disagreements before they bite.

What we check

  • Both engines can actually open the file — a file one library rejects is a red flag.
  • They agree on the number of sheets and their names.
  • They agree on the rows and columns in each sheet.
  • They agree on every cell value — and we name the exact cell where they don’t.

How it works

The page runs the same xlsx_validate operation your AI agent would call through our tools: it renders your workbook with two independent engines, diffs their canonical output, and reports whether they agree. It reads your file in memory and never stores it — this check changes nothing, it only tells you whether the file is read consistently.

Want this inside your AI agent, on your own machine, with no upload at all? Install xlsx-for-ai and ask Claude or Cursor to “validate this workbook across engines.”
